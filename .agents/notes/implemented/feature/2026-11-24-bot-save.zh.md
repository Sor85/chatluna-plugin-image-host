# Agent Note: Bot 主动把图片存入图床

Status: implemented

## Problem

图片只能由人在页面上传。用户在聊天中发来表情或图片、让 Bot「收藏这张」时，Bot 没有办法把它加入图库。

## Decision

- 新增全局工具 `image_host_save`（`src/tool.ts`），参数为对话中图片占位 `<img ref>` 的 `ref`、分类和不带扩展名的文件名。经 `@chatluna/transform` 的 `fileRefTableOf` 在 Agent 会话中解析 ref，与 v2 `look` 工具和回复中的 `<img ref>` 使用同一套编号。
- 只读取 ChatLuna 入站时已保存的原图：`storage://` 引用经 `chatluna_storage.readFile`，data URI 直接解码；URL 型数据（入站下载失败或没有存储服务）报错。工具不发网络请求，不需要防 SSRF；存储默认保留 24 小时，过期的图片无法收藏。
- 只能存入对 Bot 可见的已有分类，不新建分类，避免 Bot 造出零散分类。分类参数是可见分类的枚举，描述中列出分类说明，因为提示词不列空分类，Bot 否则看不到它们。分类集合或描述变化时撤回并重新注册工具。
- 写入经 `ImageLibrary.save`，复用上传的识别、大小上限与去重逻辑；同名时追加序号（Bot 无法回答覆盖询问），分类内已有相同内容时返回已有文件名。新图立即对 Bot 可见（用户选择不设审核）。
- 设置新增 `botSave`（默认开启，「常规」面板「允许 Bot 收藏图片」），关闭时不注册工具，而不是注册后在调用时拒绝，以免占用模型的工具列表。
- 文件名后追加占位扩展名再交给 `normalizeFileName`，避免名称中的点（如 `v1.5`）被当成扩展名截掉。

## Alternatives considered

- 同时接受 http(s) 图片地址：需要自建屏蔽内网地址的下载逻辑，用户选择只收聊天中的图片。
- 分类不存在时自动创建：分类容易变乱，用户选择只能存入已有分类。
- 默认隐藏待审核或设置项控制：用户选择总是立即可见。
