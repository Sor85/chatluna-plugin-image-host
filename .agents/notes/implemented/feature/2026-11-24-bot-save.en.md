# Agent Note: Let the bot save images into the image host

Status: implemented

## Problem

Images could only be uploaded by a person on the page. When a user sent a sticker or picture in chat and asked the bot to "keep this one", the bot had no way to add it to the library.

## Decision

- A new global tool `image_host_save` (`src/tool.ts`) takes the `ref` of an `<img ref>` placeholder in the conversation, a category and a file name without extension. The ref is resolved in the agent session with `fileRefTableOf` from `@chatluna/transform`, the same numbering the v2 `look` tool and outbound `<img ref>` use.
- Only originals ChatLuna stored on arrival are read: `storage://` references through `chatluna_storage.readFile`, data URIs decoded in place; URL-typed data (the arrival download failed or no storage service) is an error. The tool makes no network requests, so there is no SSRF surface; storage keeps files for 24 hours by default, so expired images cannot be saved.
- Images go only into existing bot-visible categories; the tool never creates categories, so the bot cannot scatter new ones. The category argument is an enum of visible categories whose description lists their descriptions, because the prompt omits empty categories and the bot would not see them otherwise. When the set of categories or their descriptions change, the tool is withdrawn and defined again.
- Writing goes through `ImageLibrary.save`, reusing upload's format sniffing, size limit and deduplication; a taken name gets a numeric suffix (the bot cannot answer an overwrite prompt), and identical content in the category returns the existing file name. Saved images are visible to the bot right away (the user chose no review step).
- A new setting `botSave` (on by default, "Let the bot save images" in the General panel) unregisters the tool when off instead of rejecting calls, so it does not take space in the model's tool list.
- A placeholder extension is appended before `normalizeFileName` so dots in the name (such as `v1.5`) are not stripped as an extension.

## Alternatives considered

- Also accepting http(s) image URLs: needs a self-built download path that blocks internal addresses; the user chose chat images only.
- Creating missing categories: categories would get messy; the user chose existing categories only.
- Hiding new images for review, or a setting for it: the user chose always visible.
