# Agent Note: 上传同名图片询问覆盖或跳过

Status: implemented

## Problem

上传的图片与分类内已有图片文件名相同时，原先自动追加 `-1`、`-2` 序号，用户无法替换旧图。要求遇到同名时弹窗询问覆盖还是跳过。

## Decision

- `image-host.image.upload` 新增可选的 `onConflict`（`src/types.ts` 的 `UploadConflictMode`），默认 `ask`：与请求开始前已有图片同名（内容不同）的文件不写入，以本次请求中的下标返回在 `UploadResult.conflicts`。客户端握有原始 `File`，询问后只重传这些文件，服务端不必暂存上传内容。
- `overwrite` 写入已有文件的路径，保留原文件名和对 Bot 的可见性，只更新内容、哈希和修改时间，并重洗该分类的随机袋；被覆盖的旧内容不再参与去重。结果在 `replaced` 中返回。
- 除覆盖、跳过外提供「保留两者」（`rename`，即原来的追加序号）：浏览器粘贴的图片都叫 `image.png`，只有覆盖或跳过时第二张截图无法加入。
- 同一请求内后到的同名文件直接追加序号，不算冲突，一次粘贴多张不会互相询问。
- 页面在全部批次结束后用 `ConflictDialog`（`client/dialogs.tsx`）统一询问一次，选择对所有冲突文件生效；关闭弹窗等同跳过。询问期间上传按钮保持禁用，新的上传提示「上一批图片仍在上传」。

## Alternatives considered

- 客户端按已有文件名预先判断：真实扩展名由服务端识别文件头后确定（`.jpg` 实为 PNG 时会改成 `.png`），客户端无法准确算出最终文件名。
- 每个文件单独选择：冲突多时操作繁琐，统一选择已覆盖常见场景。
